# Go game audio research

The window already uses pygame-ce. Its human and bot paths both call `GoGUI._record` after accepting a move. Triggering the board cue there covers both kinds of player and leaves illegal attempts silent. The terminal entry points deliberately defer loading pygame. pygame-ce mixes effects asynchronously. It can copy a generated PCM buffer into a `Sound` object, which can be reused for every move. Raw PCM must match the mixer format. Passing an in-memory PCM WAV as `Sound(file=...)` also supplies its sample rate and channel count. Python 3.14’s standard `wave` module can write the WAV to a file-like object. [pygame-ce mixer](https://pyga.me/docs/ref/mixer.html#pygame.mixer.Sound) · [Python wave](https://docs.python.org/3.14/library/wave.html)

For an original stone strike, use a short contact transient followed by a few rapidly decaying resonances. This is a design inference from Chadwick, Zheng and James, who found that short contact noise complements modal ringing for small rigid objects. The frequencies, envelope and event timing can all be authored in this project. [Authors’ paper and demonstration](https://www.cs.cornell.edu/projects/Sound/impact/)

For a bell, model the strike and the decay of individual resonances separately. Faust’s bell model exposes strike sharpness and modal decay as distinct controls. For these two cues, keep the same bell character and distinguish the outcome with register and a descending second strike on loss. For the victory horn, use sustained harmonic tones with a soft swell. For defeat, leave space between low drum strokes. These are proposed voicings for this game. [Faust bell and brass models](https://faustlibraries.grame.fr/libs/physmodels/)
